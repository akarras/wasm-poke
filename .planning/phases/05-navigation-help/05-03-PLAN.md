<task type="auto">
  <name>Task 1: Fix cursor position restoration on back navigation</name>
  <files>src/gui/panels/inspector.rs</files>
  <action>
The bug: `update_cache()` line 181 unconditionally sets `selection.instruction_cursor = 0` when function changes. But `navigate_back()` in state.rs already restores the cursor BEFORE `update_cache()` runs, so the restored position gets clobbered.

Fix approach: Track whether we're in a "back navigation" scenario and skip cursor reset in that case.

1. Add a `navigated_back` field to InspectorPanel struct:
   ```rust
   /// Flag indicating we just navigated back (skip cursor reset in update_cache).
   navigated_back: bool,
   ```

2. Initialize to false in `new()`.

3. In the `KeyAction::GoBack` arm (around line 360), set `self.navigated_back = true` BEFORE calling `navigate_back()`:
   ```rust
   KeyAction::GoBack => {
       // Backspace pressed - go back
       self.navigated_back = true;
       if selection.navigate_back() {
           // Force cache update on next frame
           self.cached_func_index = None;
       }
       None
   }
   ```

4. In `update_cache()`, make the cursor reset conditional (replace line 181):
   ```rust
   // Reset cursor when function changes via direct selection (not back navigation)
   if !self.navigated_back {
       selection.instruction_cursor = 0;
   }
   self.navigated_back = false; // Reset flag for next time
   ```

This preserves the cursor=0 behavior for normal function selection while allowing back navigation to restore the exact position.
  </action>
  <verify>
Build: `cargo build`
Test manually: Navigate to a call instruction (not at top), press Enter to goto, press Backspace - cursor should be at the original line, not at top.
  </verify>
  <done>Back navigation restores exact cursor position from navigation history.</done>
</task>
