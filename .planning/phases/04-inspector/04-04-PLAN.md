<objective>
Fix keyboard navigation to respect active tab focus.

Purpose: Currently all panels process keyboard events globally via ctx.input(), causing j/k presses to affect multiple panels simultaneously. Need to track which tab is active and only process keyboard events in that tab's panel.

Output: Keyboard navigation isolated to active tab - j/k in Inspector only moves instruction cursor, j/k in Function List only moves function focus.
</objective>

<root_cause>
All panels call handle_keyboard() using ctx.input(|i| i.key_pressed(...)) which is global.
When user presses 'j':
1. FunctionListPanel.handle_keyboard() processes it → updates selection.focus_index
2. InspectorPanel.handle_keyboard() processes it → updates selection.instruction_cursor
3. All tree panels also process it

The fix is to track which tab is currently active and only process keyboard in that panel.
</root_cause>

<task type="auto">
  <name>Task 2: Update app.rs to track active tab from egui_dock</name>
  <files>src/gui/app.rs</files>
  <action>
egui_dock's DockArea tracks which tab is focused. We need to update SelectionState.active_tab when the user clicks a tab.

1. In WasmPokeTabViewer, when ui() is called for a tab, that tab is being rendered.
   But we need to know which tab the user has clicked/focused.

2. egui_dock has `on_tab_button` callback or we can use `focused_leaf()`.

   Alternative simpler approach: In each panel's show() method, if the panel receives
   a click or any interaction, set itself as the active tab.

3. Simplest approach - track in TabViewer::ui():
   Before calling panel.show(), update selection.active_tab = *tab

In WasmPokeTabViewer::ui():
```rust
fn ui(&mut self, ui: &mut egui::Ui, tab: &mut Self::Tab) {
    // Update active tab when this tab is being rendered with focus
    // egui_dock calls ui() for the focused tab
    self.selection.active_tab = *tab;

    match tab {
        // ... existing match arms ...
    }
}
```

Wait - this won't work because ui() is called for all visible tabs, not just focused.

Better approach: Check if the UI area was clicked to set focus:

```rust
fn ui(&mut self, ui: &mut egui::Ui, tab: &mut Self::Tab) {
    // Check if this panel area was clicked - set as active
    let response = ui.interact(ui.max_rect(), ui.id(), egui::Sense::click());
    if response.clicked() || response.gained_focus() {
        self.selection.active_tab = *tab;
    }

    match tab {
        // ... existing match arms ...
    }
}
```

Actually simplest: Use the fact that egui_dock focuses tabs when clicked.
Check `ui.memory(|m| m.has_focus(ui.id()))` or use `ui.ui_contains_pointer()`
combined with mouse click.

Final approach - just set active_tab at start of ui() but ALSO pass it to panels
so they can decide whether to handle keyboard:

```rust
fn ui(&mut self, ui: &mut egui::Ui, tab: &mut Self::Tab) {
    // If user clicked in this tab area, it becomes active
    if ui.ui_contains_pointer() && ui.input(|i| i.pointer.any_click()) {
        self.selection.active_tab = *tab;
    }

    match tab {
        // ... existing match arms - pass active_tab check to panels ...
    }
}
```
