<task type="auto">
  <name>Task 1: Implement mode dispatch in main.rs</name>
  <files>src/main.rs</files>
  <action>
Rewrite main.rs to dispatch between GUI and CLI output modes:

1. Change main() signature to return `ExitCode` instead of `eframe::Result<()>`:
   ```rust
   fn main() -> std::process::ExitCode {
   ```

2. Parse CLI arguments FIRST (before any GUI imports or initialization):
   ```rust
   let cli = cli::Cli::parse();
   ```

3. Branch on output mode:
   ```rust
   match cli.output_mode() {
       cli::OutputMode::Gui => run_gui(cli.file),
       cli::OutputMode::Json => run_json_output(&cli),
       cli::OutputMode::Summary => run_summary_output(&cli),
   }
   ```

4. Implement `run_gui(file: Option<String>) -> ExitCode`:
   - Initialize env_logger
   - Create NativeOptions (existing code)
   - Call eframe::run_native (existing code)
   - Return ExitCode::SUCCESS on Ok, ExitCode::from(1) on Err
   - If file provided, pass to WasmPokeApp for auto-loading (optional enhancement)

5. Implement `run_json_output(cli: &cli::Cli) -> ExitCode`:
   - Check cli.file is Some (or "-" for stdin), else print usage error and return ExitCode::from(2)
   - Load wasm bytes (file or stdin)
   - Parse with wasm_poke::parse_wasm_from_bytes
   - Build call graph with wasm_poke::build_call_graph
   - Determine output writer (stdout or file from cli.output)
   - Call output::output_json
   - Return ExitCode::SUCCESS on Ok, ExitCode::from(1) on Err

6. Implement `run_summary_output(cli: &cli::Cli) -> ExitCode`:
   - Same pattern as run_json_output but call output::output_summary

7. Implement `load_wasm_bytes(file_arg: &str) -> std::io::Result<Vec<u8>>`:
   - If file_arg == "-", read from stdin
   - Otherwise, read from filesystem

8. Add helper for output writer:
   ```rust
   fn get_output_writer(output_path: &Option<String>) -> anyhow::Result<Box<dyn Write>>
   ```
   - None -> Box::new(std::io::stdout())
   - Some(path) -> Box::new(std::fs::File::create(path)?)

Key: GUI module is only used in run_gui() branch. If --json or --summary, GUI code is never touched (no display dependency).
